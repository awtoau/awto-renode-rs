### Read this table differently than it looks

Only **three of eight rows are numbers translation work can still move**, and
two of those are already at zero.

- **adc1's 1,192 are unreachable by bus-only replay, in principle.** The trace
  reads Status `0`, `0`, then `0x2` with **no intervening bus access** — a
  virtual-time event set it, and `Replayable` has no clock. The values
  themselves (`0x5DE`, `0x800`) come from `ADCChannel.GetSample()` dequeuing a
  queue the emulation script fills: external stimulus the trace does not record.
  A *complete* translation would still diverge. Proven, not argued —
  `src/renode-stm32/tests/adc_semantics.rs` shows the registers are wired and
  nothing moves them.
- **dma's 623 are a behaviour gap**, not a layout one. The bits are in the bank
  and land at the right positions; nothing sets them, because TCIF is read-only
  and its only C# writer reaches `DmaEngine`, which is unmapped.
- **can1's 28** are traced to the C# statement each expects: 20 need
  `CANMessage`, 7 need a withheld `WriteDoubleWord`, and **1 is neither side's
  fault** — the `.repl` writes `CAN_MCR` in its `init:` block before the CPU
  runs, so replay starts from a reset bank and never applies it.

So ~1,808 of the 1,846 cannot come down by translating better. **The real
remainder is about 38.**

## The corpus

The cut is gone (`docs/decisions/remove-the-cut.md`). 21,620 → **448,375 lines**,
192 → **4,832 types**, 72k → **1,590,724 operations**, ingest 55s.

It was removed because it was a proxy for the wrong thing — trace availability
is a fact about which peripherals have traces, not about which files an ingest
walked — and because it was measurably costing correctness: 69% of inheritance
chains truncated, 114 of 126 interfaces unresolved. Both fell to **26%** and
**12 of 126** respectively.

The `committed` tier now keys on `oracle_tier > 0`, and
`scripts/check_commit_tier.py` proves the key it replaced would have accepted a
rule no trace ever checked.

## The largest outstanding problem

**Nothing has ever executed.** 594 modules, 225 clean, zero run.

The reason is specific: the converter emits effectively nothing of the
infrastructure. `SystemBus` produces an **empty** `define_registers` from 200
members; `MappedMemory` produces 4 trivial getters from 74. Peripherals without
a bus are 594 files that compile.

The target is named and small: **`tests/unit-tests/stm32f4-erase.robot ::
Should Perform Mass Erase`** — 3 server keywords of the 64 Renode serves, 5
monitor verbs, no CPU, no ELF, no log tester. Renode's 265 Robot tests are
language-neutral and need no translation at all.

Second largest: **131 DSL-using types emit nothing** because the two register
forms do not describe how they define registers (`EFR32_GenericUSART` alone has
206 calls). That is a forms gap, now visible rather than hidden behind a name
match.

## What was wrong with our own instruments

Recorded because every number above was, until this week, computed over the
wrong denominator.

- **The compile gate reported "ALL 24 MODULES COMPILE" when cargo never ran.**
  It parsed errors from JSON and never read the exit code; a build that dies
  before compiling emits no JSON. It produced that false green during a review.
- **Four platform peripherals had never been emitted** — RCC, RTC, RNG, CRC —
  because the register-defining method was chosen **by name**, and theirs build
  their maps in a constructor. A fifth, `STM32_Timer`, selected an
  `IPeripheralContainer.Register` overload and emitted an empty map from 125
  combinator calls.
- **Five checks documented as gates gated nothing**, including
  `check_generated`, which is what turns "build the converter, do not write the
  output" into an enforced rule.
- **The refactor oracle recorded a crash as its baseline** and compared equal to
  itself forever.
- **The interleaving suite had never failed.**
- **`wrapping_*` was declared as a mapping and never existed.**

Each is fixed and each has a check that is proven able to fail.

## Rules that were wrong, not merely incomplete

Found by auditing every rule in `csharp_core.json` against the decision that a
semantic Rust lacks belongs in a runtime function
(`docs/decisions/runtime-is-the-fourth-layer.md`):

- **`<<` and `>>` at 255 sites.** C# masks the shift count to 5/6 bits
  (ECMA-334 §12.11); `1 << 32` is `1` in C# and a panic in Rust.
- **`Dictionary.Add` at 86 sites.** C# throws on a duplicate key; `insert`
  overwrites. C# `Add` and `d[k] = v` are different methods and the rule erased
  the difference.
- **`OrderBy` → `{recv}`** — a sort that does not sort.
- **`First` → `.unwrap()`** — C# throws `InvalidOperationException`.
- **LINQ keyed by name only**, so every overload took the first overload's
  template.
- **`String.Append`, `String.ToString`** keyed on the *Rust* type where the
  lookup builds the C# one: they could never match, while counting as coverage.
- **`Nullable.Value`/`HasValue` missing** at 26 sites, emitting `x.value()` on
  an `Option<T>`.

## Corrections to the previous report

- It claimed GPIO's low row was peer-call attribution (#54). Wrong: a silent
  drop in the register walker kept five of its eleven registers out of the bank.
- It claimed "nothing assembles a module into a peripheral". Out of date —
  `src/renode-stm32/src/dispatch.rs` generates the trait, a `(Bank, State)`
  struct per implementor, `new()` and the `impl`.

## Honest accounting of this week

Roughly half the work went into the instruments rather than the converter. That
was necessary once — the instruments were flattering us, and an empty register
map passed every check for weeks — but it is not repeatable as a justification.
The transpiling that did happen: four trace rows moved, five peripherals emitted
for the first time, a new rule family covering 30 types and 144 registers, four
ingest gaps closed, and constructors emitting.

The next work is the bus and the memory, because that is what stands between
594 compiling modules and one passing test.
